تعریف مسئله (Problem Definition)
عنوان پروژه: سیستم هوشمند پیشنهاددهنده محتوای آموزشی (دوره یا مقاله) مبتنی بر تحلیل معنایی متن (Semantic Text Analysis).
بیان مسئله:
در دنیای امروز، حجم عظیمی از محتوای آموزشی (مقالات پژوهشی، دوره‌های ویدئویی، کتاب‌ها و …) در پلتفرم‌های مختلف منتشر می‌شود. کاربران برای یادگیری یک موضوع خاص، با مشکل “بیش‌بار اطلاعاتی” (Information Overload) روبرو هستند. روش‌های سنتی مبتنی بر کلمات کلیدی (Keyword-based) نمی‌توانند درک درستی از “قصد کاربر” (User Intent) یا “مفهوم متن” داشته باشند. برای مثال، اگر کاربر متن “یادگیری ماشین” را وارد کند، سیستم‌های قدیمی ممکن است فقط شامل کلمات مشابه باشند، اما سیستم هوشمند باید بتواند رابطه‌ی مفهومی بین “یادگیری عمیق”، “شبکه‌های عصبی” و “الگوریتم‌های جستجو” را درک کرده و پیشنهادات مرتبط را ارائه دهد.
هدف پروژه:
طراحی و پیاده‌سازی سیستمی که با دریافت یک متن (مثلاً پاراگرافی از یک مقاله یا موضوع مورد نظر کاربر)، با استفاده از تکنیک‌های NLP (پردازش زبان طبیعی) و Content-based Filtering، مرتبط‌ترین دوره یا مقاله‌ای را که بیشترین هم‌پوشانی معنایی را با متن ورودی دارد، شناسایی و پیشنهاد دهد.

تحلیل PEAS (برای عامل هوشمند سیستم)
در طراحی سیستم‌های هوشمند، مدل PEAS (مخفف Performance, Environment, Actuators, Sensors) مشخص می‌کند که عامل (Agent) شما چگونه عمل می‌کند.
P: Performance Measure (معیارهای عملکرد)
این‌ها شاخص‌هایی هستند که تعیین می‌کنند سیستم شما چقدر “خوب” کار می‌کند (KPIs):
Precision (دقت): از میان پیشنهادهای داده شده، چند مورد واقعاً با متن کاربر مرتبط بوده‌اند؟
Recall (بازخوانی): سیستم توانسته چند درصد از تمام محتواهای مرتبط موجود در دیتابیس را پیدا کند؟
Diversity (تنوع): آیا سیستم فقط یک نوع محتوا پیشنهاد می‌دهد یا می‌تواند طیف وسیعی از منابع مرتبط را پوشش دهد؟
E: Environmentمحیط
محیطی که سیستم در آن فعالیت می‌کند:
Database of Contents: مجموعه‌ای از متادیتای دوره‌ها و مقالات (عنوان، خلاصه، برچسب‌ها، متن کامل).
User Input: متن‌های ورودی کاربران با طول‌های مختلف و زبان‌های مختلف.
Search Space: فضای وسیعِ تمامی محتواهای موجود در سیستم.
A: Actuators (عملگرها/خروجی‌ها)
بخش‌هایی از سیستم که نتیجه را به دنیای بیرون (کاربر) تحویل می‌دهند:
Recommendation Interface: نمایش لیست پیشنهادات (Ranked List) به کاربر در قالب UI.
API Response: ارسال خروجی به صورت JSON یا فرمت‌های دیگر برای استفاده در اپلیکیشن‌های دیگر.
Visual Feedback: نمایش میزان شباهت (Similarity Score) برای هر پیشنهاد.
S: Sensors (حسگرها/ورودی‌ها)
بخش‌هایی که اطلاعات را از محیط دریافت می‌کنند:
Text Input Stream: دریافت متن از طریق کادر جستجو یا آپلود فایل (PDF/TXT).
User Profile (اختیاری): دریافت تاریخچه جستجوی قبلی کاربر برای شخصی‌سازی بیشتر.
Metadata Parser: ابزاری برای خواندن و استخراج ویژگی‌ها از فایل‌های موجود در دیتابیس.


ویژگی محیط		نوع			تحلیل
مشاهده پذیری		Fully observable	سیستم می تواند به تمام داده های موجود در دیتابیس و متن ورودی کاربران دسترسی داشته باشد و تصمیم بگیرد
قطعی بودن		Deterministic		اگر ورودی و دیتابیس ثابت بمانند خروجی الگوریتم همیشه یکسان خواهد بود. مگر اینکه از روش های احتمالی در یادگیری ماشین استفاده شود.
قسمت بندی		Episodic		هر درخواست کاربر یک قسمت مستقل است تصمیم گیری برای پیشنهاد این متن مستقیما بر روی پیشنهاد متن بعدی کاربر تاثیری ندارد مگر که سیستم یادگیری آنلاین داشته باشد
ایستا یا پویا		Static			در لحظه پردازش یک درخواست دیتابیس و متن ورودی تغییر نمی کنند . محیط تا زمانی که در خواست تمام شود . تغییر وضعیت نمیدهد
گسسته یا پیوسته		Continunous		اگر چه لیست پیشنهدات کسسته است اما فضای ویژگی ها و بردار ها که متن در آن قرار میگیرد در یک فضای پیوسته قرار دارند.
تک عاملی یا چند عاملی	Single agent	سیستم پیشنهادی به تنهایی برای حل مسئله عمل نمی کند و از عامل های هوشمند دیگری که با آن رقابت یا همکاری کنند در فرآیند تصیمی گیری استفاده نمیشود.
